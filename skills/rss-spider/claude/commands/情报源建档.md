# /情报源建档 — 为主题建立可复用源目录

## 参数解析

从用户输入提取：

- `$主题或站点`：必填，可以是政策监管、AI 技术、某家公司、某个 URL。
- `$重点实体`：可选，公司、机构、产品、人物。
- `$地域`：可选，默认中国相关时使用 `zh-CN` 和 `Asia/Shanghai`。
- `$来源类型`：可选，官方、媒体、社媒、论坛、公司、搜索、列表页。

缺少 `$主题或站点` 时，要求用户补充后终止。

## 核心指令

### 1. 候选源拆解

把主题拆成候选来源：

| 来源层 | 示例 |
|---|---|
| 官方/一手 | 部委、交易所、公司官网、GitHub Release |
| 媒体/研究 | 行业媒体、主流媒体、研究机构 |
| 社区/社媒 | 微博、知乎、B 站、论坛、开发者社区 |
| 搜索补充 | Google News with `googleSource` / `googleWhen` |
| 列表页兜底 | 没有 RSS 的官网新闻列表、公告列表 |

### 2. 路由发现

对 URL 或站点关键词调用 `route-discover`：

- URL 输入：`{"url":"$url"}`。
- 站点关键词：`{"query":"$namespace"}`，注意 query 不支持空格分词。
- 已知命名空间：`{"namespace":"$namespace"}`。

### 3. 可用性验证

对候选源逐一验证：

- RSS / RSSHub route：调用 `rss-intelligence`，必须带 `summary:true`。
- 普通列表页：调用 `list-extract`。
- 中文 Google News：调用 `rss-intelligence`，带中文 locale。

### 4. 建档

按 `rss-source-policy.md` 生成 SourceDescriptor。

## 输出格式

### 一、源目录建议

| sourceId | 来源 | 等级 | 访问方式 | 主题 | 验证状态 | 维护备注 |
|---|---|---|---|---|---|---|

### 二、源覆盖评估

- 官方源是否足够。
- 媒体源是否过多。
- 社媒源是否只能作为待核验线索。
- 哪些关键来源没有 RSS。

### 三、建议沉淀的内容

按 source-catalog 结构列出，交 `rss-archive-librarian` 写入其 agent memory（`.claude/agent-memory/rss-archive-librarian/source-catalog.md`），不直接写一次性查询结果。

### 四、下一步建议

- 需要日常扫描：运行 `/每日情报简报`。
- 需要长期跟踪：运行 `/主题追踪`。
