# rss-spider · 证据协议

情报分析必须先有证据，再有判断。

## 1. 证据对象

每条进入深度分析的内容，都应在内部整理为 Evidence：

```jsonc
{
  "evidenceId": "ev_20260522_source_slug_001",
  "sourceId": "gov-miit-news",
  "sourceName": "工信部新闻",
  "title": "...",
  "link": "...",
  "publishedAt": "...",
  "fetchedAt": "...",
  "contentHash": "...",
  "topics": ["政策", "AI"],
  "entities": ["工信部", "人工智能"],
  "quotes": ["原文中可验证的短句"],
  "claims": [
    {
      "claim": "可被证据支持的事实陈述",
      "quote": "支撑该 claim 的原文片段",
      "confidence": 0.82
    }
  ]
}
```

## 2. 事实、判断、建议分层

输出时必须区分：

| 类型 | 定义 | 表达方式 |
|---|---|---|
| 事实 | 原文直接出现或多个来源共同确认 | “来源 A 发布了...” |
| 判断 | 基于事实做出的解释 | “这可能意味着...” |
| 推测 | 证据不足但值得观察 | “待核验信号...” |
| 建议 | 给用户的下一步动作 | “建议继续追踪...” |

不要把社交媒体热议、媒体评论或搜索结果标题写成已确认事实。

## 3. 引文规则

- 每个重要判断至少绑定 1 条来源链接。
- 关键事实尽量保留短引文，不复制长篇正文。
- 如果只有标题没有正文，要标注“仅标题可见”。
- 如果正文提取失败，要标注“正文未取到，基于摘要判断”。

## 4. 置信度

| 分值 | 含义 |
|---|---|
| `0.9-1.0` | 官方或一手来源明确发布，且正文可核验 |
| `0.7-0.89` | 可靠媒体或多个来源交叉支持 |
| `0.5-0.69` | 单一媒体、摘要充足但缺少原始文件 |
| `0.3-0.49` | 社媒/论坛/搜索标题信号，待核验 |
| `<0.3` | 噪声或证据不足，不应进入结论 |

## 5. 去重和冲突

- 去重优先使用 `link`，其次用 `title + sourceId + publishedAt`，再用正文 hash。
- 多家转载同一消息时，优先保留最早一手来源。
- 来源冲突时不要调和成单一结论，应列出冲突点和待核验项。
